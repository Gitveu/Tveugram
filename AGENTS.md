# AGENTS.md — форк Telegram-iOS «Legacy» под iPhone 5s / iOS 10.3.3

## 0. Миссия

Собрать поддерживаемый форк официального клиента Telegram для **iPhone 5s (A7, arm64, 1 ГБ RAM) на iOS 10.3.3** (устройство джейлбрейкнуто, апгрейд на 12.5.8 не рассматривается).

Требуемый результат:
1. Приложение стабильно запускается, работает логин по номеру, работает вся медиа-отправка (в т.ч. **кружки** — round video messages).
2. Присутствует **весь функционал апстрима** (см. §7), **кроме дизайна Liquid Glass**.
3. Работает **локальный Premium** (смена иконки, много аккаунтов и прочие клиентские плюшки) — см. §8.

Обязательное правило: **форк должен оставаться максимально близким к апстриму**, чтобы фичи можно было подтягивать и дальше. Никаких «переписал всё по-своему».

---

## 1. Жёсткие ограничения платформы

| Параметр | Значение |
|---|---|
| Устройство | iPhone 5s (arm64, A7, PowerVR G6430) |
| ОС | **iOS 10.3.3** (deployment target = 10.3) |
| RAM | 1 ГБ — главный дефицит |
| Джейлбрейк | h3lix (10.0–10.3.3, 64-bit) |
| Установка | AppSync Unified, ad-hoc/ldid-подпись |
| 32-бит | iOS 10 — последняя ОС с 32-битными приложениями (это причина оставаться на 10.3.3) |

**Следствия, которые нельзя игнорировать:**
- Нет `Network.framework` (iOS 12+) — сетевой стек должен ходить через BSD-сокеты.
- Нет `safeAreaLayoutGuide` (iOS 11) — нужен фолбэк на `topLayoutGuide`/`bottomLayoutGuide`.
- Нет `UIScene` (iOS 13) — только классический `UIApplicationDelegate` + `UIWindow`.
- Нет SwiftUI (iOS 13), нет `UIContextMenuInteraction` (iOS 13), нет `UINavigationBarAppearance` (iOS 13), нет semantic colors (iOS 13).
- Нет `libswift_Concurrency` в системе (только iOS 13+) — если код использует `async/await`, библиотеку нужно **вшивать** и проверять её работоспособность на 10.3.3 (это отдельный риск, см. §5.4).
- Нет системного Swift-рантайма (ABI-стабильность только с iOS 12.2) → Swift-библиотеки обязаны быть **вшиты в бандл**.
- GPU очень слабый → блюры, рефракция, крупные размытия — дорого.

---

## 2. Non-goals (что НЕ делаем)

- **Liquid Glass / новый дизайн 2025–2026.** Не портируем, не включаем. Классический вид.
- iPad-специфика, visionOS, watchOS, SwiftUI-экраны.
- Серверные фичи, которые клиент не может обеспечить (большие файлы >2 ГБ, транскрипция, emoji-статус, «быстрая загрузка») — только помечаем как «частично».
- Изменение UI-структуры «под себя». Только минимально необходимое.

## 3. Базовая версия для форка

### Решение: `release-11.12`

Обоснование:
1. Это **последний релиз с минимальной ОС ≤ 12.2** (в 11.13 min уже iOS 13.0). Значит кодовая база ещё не содержит жёстких предположений про API iOS 13+, и дельта для бэкпорта на 10.3.3 — **минимальная среди «современных» версий** (только iOS 11 и iOS 12).
2. **Глас отсутствует by design** — не нужно ничего выпиливать.
3. Уже есть весь «классический» набор: истории, топики, папки, реакции, подарки/звёзды, мультиаккаунт, смена иконки, темы, кастомные цвета.
4. min OS = 12.2 совпадает с границей ABI-стабильности Swift → ситуация с рантаймом управляемая и явная.

### Лестница фолбэков (если 11.13.3 упрётся)
- **Проще:** `release-9.6.5` — min iOS 11, есть готовые `if #available(iOS 11)`-гварды, Swift-либы вшиты. Дельта всего одна версия. Меньше фич.
- **Хочется 100% фич без черри-пиков:** `release-13.1.1` — но дельта 11/12/13/14/15 и надо выпиливать глас. Использовать только если черри-пики в 11.13.3 окажутся невыносимыми.

### Обязательные черри-пики из апстрима
Делать **точечно**, по одному коммиту, с тестом после каждого:

| Что | Откуда | Приоритет |
|---|---|---|
| Фикс ClientHello/TLS в `MTProtoKit` (от него зависит логин) | diff `release-12.5.2..release-12.6.3` | P0 |
| Заметки к контактам | 12.1.1 | P6 |
| Реакции на звонках | 12.1.1 | P6 |
| Чек-листы (новый тип сообщения) | 12.x | P6 |
| AI-саммари (клиентская часть) | 12.3 | P6 |
| Gift crafting | 12.7+ | P7 |
| Цвета профиля/имени (клиентский рендер) | 12.x | P6 |

Правило: **если патч тянет за собой глас — вырезать глас, не тащить.**

## 4. Тулчейн и сборка

- Сборка: **Bazel** (`bazel build Telegram`), как в апстриме.
- Min OS задаётся в `Telegram/BUILD` (`minimum_os_version`) и в конфиге сборки.
- **Сначала выяснить реальный минимум тулчейна.** Если текущий Xcode не даёт выставить deployment target ниже 12 — собирать с 12 и **патчить Mach-O** (`LC_BUILD_VERSION` / `LC_VERSION_MIN_IPHONEOS`) до 10.3, затем ловить рантайм-проблемы. Записать результат в `docs/TOOLCHAIN.md`.
- Если тулчейн позволяет 10.3 — выставлять 10.3 сразу и держать `#available`-гварды «живыми» (иначе компилятор их вырежет).
- `ALWAYS_EMBED_SWIFT_STANDARD_LIBRARIES = YES` — Swift-рантайм обязателен в бандле.
- Если используется `async/await` — вшить `libswift_Concurrency.dylib` и **проверить на устройстве** (см. §5.4).
- Отпечаток сборки: сохранять `bazel`-версию, Xcode, дату — в `docs/BUILD.md`.

## 5. План бэкпорта (обязательный аудит API)

Пройтись по кодовой базе и для каждого пункта сделать `if #available(iOS N, *)` с фолбэком. **Восстанавливать гварды из git-истории**: `git log -S` по удалённым `#available(iOS 11`, `#available(iOS 12` — раньше они были, их вырезали при поднятии min OS.

### 5.1 iOS 11 (нет на 10.3.3)
- `safeAreaInsets` / `safeAreaLayoutGuide` / `additionalSafeAreaInsets` → `topLayoutGuide` / `bottomLayoutGuide`.
- `UITableView` swipe actions (`UIContextualAction`, `UISwipeActionsConfiguration`) → легаси-свайпы.
- Drag & drop (`UICollectionViewDragDelegate`, `UIDropInteraction`).
- Large titles (`prefersLargeTitles`).
- `UIScrollView.contentInsetAdjustmentBehavior`.
- `UIFontMetrics` (dynamic type).
- `PDFKit`, `Vision`, `CoreML`, `ARKit` — по возможности отключить/зафолбэчить.
- `UIBarButtonItem` + `searchController` в `navigationItem`.

### 5.2 iOS 12
- `Network.framework` → проверить, что сетевой слой использует BSD-сокеты, а не `NWConnection`. **Это главный подозреваемый по сломанному логину** (см. §6.1).
- `WKHTTPCookieStore` (iOS 11) / cookie-API.
- Siri Shortcuts (`INInteraction`) — можно заглушить.
- `NFC`, `QLPreviewController` AR-режим.

### 5.3 iOS 13 (для черри-пиков)
- `UIContextMenuInteraction` → фолбэк на `UILongPressGestureRecognizer` + `UIAlertController`.
- `UINavigationBarAppearance` → старый API `UINavigationBar`.
- `UIScene` → классический жизненный цикл.
- semantic colors → свои константы темы.

### 5.4 Swift-рантайм
- Вшить все нужные `libswift*.dylib`, включая `libswift_Concurrency.dylib`, если есть `async/await`.
- Если `libswift_Concurrency` не заводится на 10.3.3 — рассмотреть вариант **переписать критичные `async`-места на GCD** только там, где это дёшево.

## 6. Известные регрессии прошлых форков (обязательно к фиксу)

В предыдущих форках (базы 8.8 и 11.11) не работали **кружки** и **логин по номеру**. Ниже гипотезы и направления.

### 6.1 Логин по номеру (P0)
Гипотезы:
1. Клиент ходит через `Network.framework` (iOS 12+) и на iOS 10 нет рабочего транспорта → вернуть/включить легаси-путь на BSD-сокетах.
2. Отпечаток TLS `ClientHello` отвергается сервером → черри-пик фикса из 12.6.3.
3. `api_layer` / `initConnection` не совместим → сверить с апстримом, не занижать слой.
4. Крипто/`SecKey`/`SecTrust` пути, зависящие от iOS 11+.

Чек-лист приёмки: вход по номеру, приход SMS-кода, ввод кода, регистрация нового аккаунта, вход в существующий, 2FA-пароль.

### 6.2 Кружки (P0)
Гипотезы:
1. Запись видео-сообщения ушла на **HEVC** (`AVVideoCodecType.hevc`, iOS 11+) → принудительно H.264 на iOS 10.
2. Использование iOS 11+ API в `AVCapture*` / `AVAssetWriter` / `VideoToolbox`.
3. Плейбек через `AVPlayer` + маска — обычно ок, проверить отдельно.

## 7. Feature parity — что портируем, что нет

**Портируем:** весь список из §3 «обязательные черри-пики» + новые типы голосований/опросов, улучшения папок, реакции, подарки, истории-улучшения.

**Не портируем:** Liquid Glass, новые анимации рефракции, «энергосберегающие» тумблеры, привязанные к гласу.

**Правило для агента:** при черри-пике фичи сначала вытащить её в изолированный коммит на апстриме, затем перенести. Если фича неотделима от гласа — либо оставить глас локально (и тогда явно пометить), либо отбросить фичу. Решение фиксировать в `docs/FEATURES.md` (таблица: фича / статус / откуда / риск).

## 8. Локальный Premium (клиентская эмуляция)

### Цель
Разблокировать **клиентские** премиум-плюшки без реальной подписки: смена иконки, много аккаунтов, лимиты папок/пинов, бейдж, косметика.

### Реализация
1. Модуль `LocalPremium` (флаг в `UserDefaults`, дефолт ON, плюс тумблер в настройках).
2. **Найти все гейты**: `grep -rn "isPremium"` по `TelegramUI`, `TelegramCore`, `Account*`. Централизовать чтение через `LocalPremium.override(_ value: Bool) -> Bool`.
3. Форсить `isPremium = true` для текущего аккаунта (патч на уровне аккаунта/пользователя, а не сервера).
4. Поднять клиентские лимиты:
   - аккаунты: 3 → 6 (константа в `AccountManager`);
   - папки: 10 → 100 (или «безлимит»);
   - закреплённые чаты: 5 → 10.
5. Включить **смену иконки**: модуль `AppIcons`/`ChangeAppIcon`, убедиться что скомпилен и доступен на **iOS 10.3+** (`UIApplication.setAlternateIconName`, iOS 10.3). Добавить `CFBundleAlternateIcons` в Info.plist и PNG-иконки. Проверить, что набор иконок не раздувает бандл до неприличия.
6. Включить клиентскую косметику: цвета профиля/имени, обои из премиум-набора, анимации сообщений.
7. Показать бейдж Premium в профиле и экран «Premium активен» без апселла.

### Честные ограничения (обязательно отразить в UI)
Локальный премиум **не делает** серверные вещи: файлы >2 ГБ, ускоренная загрузка, транскрипция, emoji-статус, премиум-реакции/стикеры, отсутствие рекламы в каналах. Ошибки сервера обрабатывать мягко (например, аплоад большого файла → понятное сообщение).

### Приёмка
- Смена иконки работает и переживает перезапуск.
- 6 аккаунтов добавляются и переключаются.
- Папок больше 10 создаётся.
- Бейдж виден, апселл не мешает.
- Тумблер выключения возвращает обычное поведение.

## 9. Производительность и память (A7 / 1 ГБ)

- Бюджет: не раздувать кэши, ограничить `maximumNumberOfSurroundingMessages`, уменьшить превью-кэши.
- Не включать дорогие блюры без нужды; проверить частоту `UIVisualEffectView`.
- Замеры: время холодного старта, потребление RAM в списке чатов, потребление RAM в чате с 1000 сообщений, потребление при проигрывании видео. Фиксировать в `docs/PERF.md` до/после каждого релиза.
- Регресс по RAM > 10% между сборками — блокирующий.

---

## 10. Подпись, установка, пуши

- Bundle ID: решить, оставлять ли оригинальный. Оригинальный ID помогает с путями, но **пуши через APNs на переподписанном форке — отдельный риск**: при отсутствии пуш-энтайтлмента уведомления будут только в активном приложении. Проверить и зафиксировать результат в `docs/PUSH.md`; при необходимости рассмотреть PushFix-подход.
- Установка: `AppSync Unified`, подпись `ldid`, установка поверх (не рядом с официальным клиентом, если bundle ID совпадает).
- Версия: `CFBundleShortVersionString` оставлять честной (11.13.3). Если сервер начинает просить апдейт — отдельным экспериментом поднять строку версии и проверить, не включатся ли серверные фичи, которых клиент не умеет.

## 12. Правила работы агента

1. Один коммит — одна задача. Никаких «заодно отрефакторил».
2. Перед коммитом — сборка. Сломанный билд не коммитить.
3. Любой API новее 10.3 — только под `if #available`. Не полагаться на «и так сойдёт».
4. Все компромиссы и костыли — в `docs/DECISIONS.md` с датой и причиной.
5. Никогда не заявлять «работает», если не проверено на устройстве. Формулировать «собрано, на устройстве не проверено».
6. При черри-пике — указывать исходный коммит/тег апстрима.
7. Не менять апстримный стиль кода. Форк должен легко ребейзиться.
8. Веди `docs/REGRESSIONS.md`: что уже ломалось и как починено (начинать с §6).
